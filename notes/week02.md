#提示词工程
(1)用""""""包含，角色设定[system]，例子提供(Few-Shot)[user和assistant],执行步骤(Chain-of-Thought)[system或user],参考文本[user]，任务目标[system]

(2)零样本学习(Zero-Shot):基于模型见过的内容，不提供任何示例，让模型根据自己已知的内容做属性迁移

(3)Few-Shot:给少量示例，让模型知道要怎么返回内容

(4)
    system
    持久化的角色与身份：定义模型“是谁”，例如“你是一位有5年经验的AI测试专家”。
    
    全局行为规范与安全边界：设定模型必须始终遵守的规则，如“不得评论竞争对手”、“不确定的信息不要猜测”。
    
    输出格式的硬性要求：如果所有回复都必须遵循某种格式，应写入 system，例如“回复控制在150字以内”、“称呼用户为‘您’”。
    
    应用级的背景知识：对所有用户查询都通用的事实性信息，如产品的退款政策、运费规则等。
    
    固定行为模式的指令：如果你希望模型总是先思考再回答，可以将“你总是先给出推理步骤，再给出最终答案”作为固定指令放入 system。
    
    关键判断：如果一条指令你希望它在下一次、下十次请求中都无需重复就自动生效，就应放入 system。
    
    user
    用户的实际问题或任务：这是最核心的用途，如“帮我解释一下Spring AOP的工作原理”。
    
    本次请求特有的参考数据：RAG检索到的文档、需要分析的数据等，都应作为本次请求的上下文，与问题一起放入 user 消息中。
    
    仅对单次任务生效的指令：如果只想让当前这个问题逐步推理，可以在 user 消息中附加“这道题请一步步算”。
    
    临时的输出格式要求：例如“这次请用英文回答”、“输出不超过200字”等仅对当前回复有效的参数。
    
    针对特定推理模型的策略：对于DeepSeek-R1、QwQ、OpenAI o-series这类专门的推理模型，官方建议将CoT等指令放入 user 消息，而 system 最好留空或仅放最基础的安全设定。
    
    assistant[在写入时可以用json.jumps将内容转换为json格式再写入]
    代表了模型的历史回复，最关键的用途就是记录Few-Shot的期望输出部分等
    
    必须与 user 消息配对：一个 assistant 示例消息必须紧跟在一个 user 示例消息之后，构成一个完整的“输入-输出”对，绝不能单独出现。
    
    示例中的CoT展示：如果想通过模仿来教模型如何进行推理，可以在 assistant 的示例回复中完整展示包含推理步骤的答案。

(5)在写提示词工程时建议单独写几个变量去记录例子等，用循环如for key,value in a_example添加到历史消息中

#-------JSON(python中可以调用json模块)
(1)JSON分为JSON对象和JSON数组
    JSON对象相当于字典，在打括号内有不同名字的Key和Value
    JSON数组相当于存于列表中的字典

(2)
    s = json.dumps(字典或列表,ensure_ascii=False):可以把python字典或列表转换为json字符串赋值给s
        其中的ensure_ascii = False可以确保中文正常显示，汉字不转换为ASCII码
    s = json.leads(json字符串):将json字符串转换为python字典或列表赋值给s
